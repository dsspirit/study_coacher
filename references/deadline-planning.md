# 期限倒排规划协议（zcode 专用）

> 触发：学生说「我想在 X 前学会 Y」/ 建新计划 / 周复盘发现滞后。算术交给 `scheduler.py plan-check`，判断和取舍是 zcode 的活。

## 倒排六步

1. **定锚**：deadline（学生给的日期；给的是时长如「一个月」就换算成绝对日期并让学生确认）→ 写进学习计划 frontmatter `deadline`。
2. **定预算**：每周可投入小时（学生口述，默认 8）→ `weekly_hours`。宁可低估：预算虚高的计划第一周就破产。
3. **列块**：把领域内容拆成可独立验收的块（一篇讲义 / 一组论文 / 一个实操都算一块）。拆法看 [[sources-checklist]]。
4. **算账**：每块约 1.5 h（读 + 作答 + 次日默写摊销）。`scheduler.py plan-check` 直接输出：剩余小时 vs 可用小时、预计完成日 eta、滞后 lag_days。
5. **砍或加**：预算不够时按优先级砍块（前沿预测 > 变体谱系 > 主线推导——**核心主线最后砍**），或学生加时。别默默砍：砍什么写进变更记录，学生点头。
6. **里程碑**：每阶段给日期（阶段期限），写进计划。里程碑是预警器：过点没走完 = 复盘信号，不是惩罚理由。

## 体检节奏

- 每次批改收尾瞄一眼：lag_days > 0 就在「下一步」里提一句（不唠叨，一句就好）。
- 周日复盘必跑 `plan-check`：滞后 → 和学生决定砍块/加时/挪 deadline，三选一，写变更记录。
- 学生提前完成：不加速塞新块（间隔重复要时间发酵），把余量留给复习深度，或和学生商量提前进下一阶段。

## 红线

- 新内容日限照旧（块可以排队，一天最多学 2 块）——赶进度不等于塞爆工作记忆（T047）。
- deadline 前最后 20% 时间留给「出师自测 + 错题重考」，不排新块。
- 计划是预测不是合同：每周修正一次，比一年不动然后崩盘强。
