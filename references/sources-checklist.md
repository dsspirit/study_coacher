# 学习源接入 checklist（zcode 专用）

> 触发：学生说「接入/学习这个：<源>」，或创建学习计划时带源。SKILL.md 只说协议骨架，本文件是逐步操作清单。
> 总原则（D5）：**一切外部源先材料化为 vault md** 再进学习循环——一条流水线一种格式，批注/出题/批改协议不为源特化。

## 通用前置

1. 确认 zone 与学习计划存在（没有就先跑 setup + 计划访谈）。
2. 问清（或从源本身推断）学生的目标深度：了解 / 会用 / 能讲给别人 / 能推导实现——深度决定分块粒度。
3. 估算体量：多少个可独立成块的单元，对照期限算预算（见 [[deadline-planning]]）。

## 源类型 A · vault / 知识库（已有一堆笔记）

- [ ] 读 vault 的阅读路线图 / MOC（00_地图/），没有就扫目录结构（大范围扫描委派 explorer，主会话只收结论）
- [ ] 按「已成熟可直接进路线 / 半成品需补讲义 / 只有标题是坑」三档分类
- [ ] 半成品：补写讲义（走 vault 写作规范：大白话/拷问/论文表/参考四节），或出 material 包让学生先读现状再定
- [ ] 把可用的块按依赖顺序折进学习计划路线（frontmatter 指针不动，变更记录留痕）

## 源类型 B · PDF / 论文

- [ ] 下载/定位文件：arXiv 用 arxiv-cli skill；本地 PDF 用 `pdftotext` 抽文本（本机可用，见 ops 记忆）
- [ ] 文件放 `papers/`（vault 既有附件目录约定）
- [ ] 生成文献笔记 `07_文献笔记/文献_<短名>.md`：写作规范四节齐全（大白话 = 这篇论文在干嘛、一段话；拷问 = 方法的成立前提与失败模式；关键论文表可省；参考 = 原文链接）
- [ ] 登记：写作规范文末登记表追加文件名（[[文件名]] 纯链接）
- [ ] 进路线：文献块默认放对应阶段末尾（先有地图再读文献）

## 源类型 C · 网页 / 博客 / 文档站

- [ ] 抓取用本地 firecrawl MCP（`mcp__firecrawl__*`），质量不佳回退 web_reader；零散短文可用 WebFetch
- [ ] 内容整理成主题笔记（归 01-06 对应学科目录），标注来源 URL 与抓取日期（内容会变）
- [ ] 若是文档站（多页），只材料化学生目标相关的页，别全站搬运
- [ ] 登记同 B

## 源类型 D · 代码仓

- [ ] clone 到 **vault 外**（如 `~/code/<repo>`）——vault 不存代码
- [ ] 委派 explorer 摸仓库：README/目录结构/核心模块/入口/测试怎么跑，产出结构摘要（主会话只收结论）
- [ ] vault 内写「导读文档」`<学科目录>/<repo短名>导读.md`：这个仓库是什么、目录地图、按学习目的的阅读顺序、关键文件 `路径:行号` 索引
- [ ] 学习方式：导读进路线当 material 块；代码实操出 drill 包（学生改代码/跑测试，作答贴 diff 或结论）
- [ ] 登记同 B

## 收尾（所有类型共用）

- [ ] 学习计划路线更新 + 变更记录一行；`scheduler.py plan-check` 复查预算
- [ ] 出第一个 material 包（导读/总览），把新源接入的消息面告诉学生：新加了什么块、预计多久
- [ ] 新块对应新卡入队遵守日限 5 张
